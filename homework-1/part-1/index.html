Private Key → Public Key in Ethereum

Ethereum turns a private key k into a public key Q with one operation: elliptic-curve scalar multiplication Q = kG on secp256k1. This page does the same on the toy curve y² = x³ + 7 (mod 17), animates the algorithm step by step, and runs statistical experiments on the outputs.

01

The toy curve

secp256k1, the curve used by Bitcoin and Ethereum, is y² = x³ + 7 over the prime field Fp with p = 2²⁵⁶ − 2³² − 977. The toy curve keeps the same equation but uses p = 17, so every point fits on a 17 × 17 grid.

The points of the curve, together with a point at infinity O, form a finite abelian group. Its size is #E = 18, and the base point G = (1, 5) has order 9: 9G = O, so the multiples of G repeat with period 9.

02

Point addition

The group law is the chord-and-tangent rule. Draw the line through P and Q, find the third intersection with the curve, and reflect it across the x-axis. Over Fp every division is a multiplication by a modular inverse, computed with the extended Euclidean algorithm.

When P and Q are the same point (doubling, P + P = 2P) there is no line through two distinct points: use the tangent to the curve at P instead, then continue in the same way.

Special cases: P + O = P, and P + (−P) = O, where −(x, y) = (x, −y mod p) (the line is vertical and "meets the curve at infinity").

03
Computing Q = kG

        
Scalar multiplication is repeated addition, kG = G + G + … + G.
          Adding one G at a time costs k − 1 additions. Double-and-add reads the bits of k and costs at most
          2·log₂k operations. This is what makes secp256k1 practical with k ≈ 2²⁵⁶.
          For example, if we take the base point G = (1, 5) and the private key k = 6,
          we get the toy public key Q = 6G = (5, 8).

    What the experiments show
    
            
      
              
    • p = 17 is degenerate. With G = (1, 5), only 8 public keys exist. x takes 4 values ({1, 2, 5, 12}), each exactly twice per period.
                Every statistic is fully determined by the cycle of length 9, and in sweep mode the scatter plot is a repeating pattern.
      • 
              
    • The base point matters. Choosing G of order 2, 3 or 6 shrinks the key space further. A generator of order 18, such as (6, 6), reaches every point.
                Real curves use prime order so that every G ≠ O generates the whole group.
      • 
              
    • Large prime-order curves look random. Chi-square tests over ⟨G⟩ do not reject uniformity, correlations are ≈ 0, and the bit-flip
                experiment changes about half of the output bits. The top-bit bias remains, caused by the range [0, p) and not by a weakness.
      • 
            
    
          
    
          
    
            
    Why that is not the same as a hash
    
            
    A hash function is designed to destroy structure: it should behave like a random function, so that
              knowing H(m) says nothing about H(m′) for any related m′. Avalanche, bit balance and decorrelation are
              symptoms of that goal, and they can be measured statistically.
    
            
    Scalar multiplication is designed to keep structure. It is a group homomorphism
              k ↦ kG from Zn to ⟨G⟩. This structure is what enables ECDSA signatures, Diffie–Hellman,
              and BIP-32's public-key derivation in Part 2 (child public key = parent public key + t·G).
              Its security rests only on the hardness of the ECDLP. That is not a statistical property: the outputs can pass every
              test of section 05 and still satisfy exact algebraic relations.
    
            
    Takeaway: statistical tests can refute randomness but cannot prove one-wayness.
              The toy curve passes some tests and is trivially invertible. secp256k1 fails the "no structure" test by design and is still believed one-way.
