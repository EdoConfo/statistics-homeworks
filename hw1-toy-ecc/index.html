Homework 1 · Public-key cryptography

Private key → public key
on a toy elliptic curve

Ethereum turns a private key k into a public key with one operation: elliptic-curve scalar multiplication Q = kG on secp256k1. This page does the same on the toy curve y² = x³ + 7 (mod 17), animates the algorithm step by step, and runs statistical experiments on the outputs.

01

The toy curve

secp256k1, the curve used by Bitcoin and Ethereum, is y² = x³ + 7 over the prime field Fp with p = 2²⁵⁶ − 2³² − 977. The toy curve keeps the same equation but uses p = 17, so every point fits on a 17 × 17 grid.

The points of the curve, together with a point at infinity O, form a finite abelian group. Its size is #E = 18, and the base point G = (1, 5) has order 9: 9G = O, so the multiples of G repeat with period 9.

Why exactly 18 points? Since 17 ≡ 2 (mod 3), the map x ↦ x³ is a bijection of F17. For every y there is exactly one x with x³ = y² − 7, which gives 17 affine points, plus O: p + 1 = 18. The curve is supersingular. secp256k1 has p ≡ 1 (mod 3), and its group has prime order n ≈ 1.16 × 10⁷⁷ (cofactor 1).

Because 18 = 2 · 3² is not prime, the toy group has subgroups of order 2, 3, 6 and 9, and a key k only matters modulo the order of G: here k mod 9.

02

Point addition

The group law is the chord-and-tangent rule. Draw the line through P and Q, find the third intersection with the curve, and reflect it across the x-axis. Over Fp every division is a multiplication by a modular inverse, computed with the extended Euclidean algorithm.

P ≠ Q:   λ = (y₂ − y₁) · (x₂ − x₁)⁻¹   |   P = Q:   λ = (3x₁² + a) · (2y₁)⁻¹
x₃ = λ² − x₁ − x₂     y₃ = λ(x₁ − x₃) − y₁     (all mod p)

Special cases: P + O = P, and P + (−P) = O, where −(x, y) = (x, −y mod p) (the line is vertical and "meets the curve at infinity").

Worked example, 2G. With G = (1, 5), a = 0: λ = 3·1² · (2·5)⁻¹ = 3 · 10⁻¹ = 3 · 12 = 36 ≡ 2 (since 10 · 12 = 120 ≡ 1 mod 17). Then x₃ = 2² − 1 − 1 = 2 and y₃ = 2(1 − 2) − 5 = −7 ≡ 10, so 2G = (2, 10).

// ecc.js (excerpt)
export function addDetailed(C, P, Q) {
  const { p, a } = C;
  if (P === INF) return { kind: 'identity', result: Q };
  if (Q === INF) return { kind: 'identity', result: P };
  if (P.x === Q.x && mod(P.y + Q.y, p) === 0n)
    return { kind: 'inverse', result: INF };      // P + (-P) = O

  const doubling = P.x === Q.x && P.y === Q.y;
  const num = doubling ? 3n * P.x * P.x + a : Q.y - P.y;
  const den = doubling ? 2n * P.y           : Q.x - P.x;
  const lambda = mod(num * inv(den, p), p);
  const x3 = mod(lambda * lambda - P.x - Q.x, p);
  const y3 = mod(lambda * (P.x - x3) - P.y, p);
  return { kind: doubling ? 'double' : 'add', lambda,
           result: { x: x3, y: y3 } };
}

03

Computing Q = kG

Scalar multiplication is repeated addition, kG = G + G + … + G. Adding one G at a time costs k − 1 additions. Double-and-add reads the bits of k and costs at most 2·log₂k operations. This is what makes secp256k1 practical with k ≈ 2²⁵⁶.

    05
    The way back: why Q does not reveal k
    
        
    
          
    
            
    Going forward is cheap. Going backward, from Q to k, is the Elliptic Curve Discrete Logarithm Problem (ECDLP).
              No method is known that does much better than generic algorithms such as Pollard's rho, which need about
              √n group operations.
    
            
    On the toy curve the "hard" problem is trivial: just try k = 1, 2, 3, … until kG = Q.
              The one-way property comes from the size of the group, not from the formulas.

              roughly 10⁹ times the age of the universe.

    5 · Structure test: what a statistic cannot see
    
        
    
          
    
            
    Relation tested on random inputsEC: k ↦ kGHash: m ↦ SHA-256(m)
    
            
          
    
        
    
        
    The bit-flip relation means that anyone who knows Q can compute the public key of k ⊕ 2ⁱ without knowing k,
          because it is either Q + 2ⁱG or Q − 2ⁱG. The avalanche histogram above looks "random" anyway: avalanche statistics measure
          how much the output changes, not whether the change is predictable.

    What the experiments show
    
            
      
              
    • p = 17 is degenerate. With G = (1, 5), only 8 public keys exist. x takes 4 values ({1, 2, 5, 12}), each exactly twice per period.
                Every statistic is fully determined by the cycle of length 9, and in sweep mode the scatter plot is a repeating pattern.
      • 
              
    • The base point matters. Choosing G of order 2, 3 or 6 shrinks the key space further. A generator of order 18, such as (6, 6), reaches every point.
                Real curves use prime order so that every G ≠ O generates the whole group.
      • 
              
    • Large prime-order curves look random. Chi-square tests over ⟨G⟩ do not reject uniformity, correlations are ≈ 0, and the bit-flip
                experiment changes about half of the output bits. The top-bit bias remains, caused by the range [0, p) and not by a weakness.
      • 
            
    
          
    
          
    
            
    Why that is not the same as a hash
    
            
    A hash function is designed to destroy structure: it should behave like a random function, so that
              knowing H(m) says nothing about H(m′) for any related m′. Avalanche, bit balance and decorrelation are
              symptoms of that goal, and they can be measured statistically.
    
            
    Scalar multiplication is designed to keep structure. It is a group homomorphism
              k ↦ kG from Zn to ⟨G⟩. This structure is what enables ECDSA signatures, Diffie–Hellman,
              and BIP-32's public-key derivation in HW2 (child public key = parent public key + t·G).
              Its security rests only on the hardness of the ECDLP. That is not a statistical property: the outputs can pass every
              test of section 06 and still satisfy exact algebraic relations.
    
            
    Takeaway: statistical tests can refute randomness but cannot prove one-wayness.
              The toy curve passes some tests and is trivially invertible. secp256k1 fails the "no structure" test by design and is still believed one-way.
